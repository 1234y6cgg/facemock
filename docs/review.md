# 每日计划、薄弱点与延迟复测

首页 `/` 为今日练习；`/review` 为知识点与证据；`/progress` 为状态分布与回答时间线。原完整模拟移至 `/mock`，面试、简历及报告深链接不变。语音确认文本复用同一套评估与复习规则；项目话术保留独立事实反馈，不把表达评价转换为技术知识掌握度。

## 规则

个人档案保存在 MySQL。默认时区 `Asia/Shanghai`，每日推荐 3 题，间隔为三个递增整数 `[1,3,7]`，至少两次分开的独立有效复测通过才标记已巩固。可在页面修改时区、题量、间隔、通过次数，暂停或恢复。

| 情况 | 掌握状态与安排 |
| --- | --- |
| 没有有效判定 | 未练习，无到期任务；无法判断单独显示 |
| 部分、缺失或错误 | 练习中，连续通过证据归零，下一本地日期加第一档间隔 |
| 正确但无足够独立复测 | 待巩固；首次有效回答安排第一档间隔 |
| 到期独立首答正确 | 累计通过次数，使用下一档间隔，最终重复第三档 |
| 达到通过次数 | 已巩固，仍保留下一次复习日期 |
| 有辅助重答 / 普通独立练习 | 可以形成有效学习证据，不能累计独立复测通过 |
| 未评估、失败、无法判断 | 不推进掌握，不推迟既有到期日 |

**独立复测**必须通过 `/api/review/sessions` 建立，服务端确认至少一个目标知识点已经到期。第一条回答且无提示/解析辅助才可累计；同题其余知识点也分别按自己的到期日核验。重答、普通练习和专项追问不自动算延迟复测。每个知识点在同一本地日期最多增加一次通过证据。首次提交前，后端拒绝复测提示和提前解析，前端隐藏旧答案。

日期按配置时区的本地自然日计算，在当地午夜换日；这里采用日历日期规则，而非保证相隔精确 24 小时。暂停停止推荐和开复测，不冻结时间；恢复后，每知识点仍只有一项任务，不因逾期数天而叠加。跳过仅影响当前日期的推荐，不删除证据、不推迟任务，次日恢复参与排序。

同一回答只采用其第一条成功评估，依据稳定知识点 ID 合并不同题目/追问的证据。当前默认题库有 24 题、72 个知识点，基础题之间知识点不同；专项追问复用原知识点。新增题可以复用同一 ID，无需按文本猜测。

## 持久化与重算

`practice_evaluation` 的成功记录及不可变回答是事实账本。`knowledge_progress` 为知识点投影，`review_task` 每知识点最多一行，`review_profile` 保存个人设置。查询计划/进度时在同一事务内锁定个人配置、确定性重放账本并刷新投影，重复查询不会累计次数或增加任务。

删除练习后，下次查询自动从剩余账本重算；已删除的基线不会凭后来的复测创造通过次数。清空 Redis、删除投影缓存、应用重启不会丢失 MySQL 中的证据和设置。修改规则或时区会按新规则重算，原回答、评估与引用快照不会被覆盖。

这是单人单应用实例的实现，重算会扫描个人成功评估；大量历史或多用户服务需要分页增量投影、事件版本与所有权控制。当前不公开多用户部署。每知识点页面展示最近 30 次证据，累计统计使用完整账本。

## 接口

| 接口 | 行为 |
| --- | --- |
| `GET /api/review/today` | 当天推荐、到期数量和设置；排序为到期 → 尚未解决错误/遗漏 → 新题，同一道基础题去重 |
| `GET /api/progress/knowledge-points` | 状态、到期日、原话、关联练习、辅助标记、独立复测与无法判断记录 |
| `PUT /api/review/preferences` | `timezone`、`dailyLimit`、`intervals`、`requiredPasses`、`paused`；服务端校验范围 |
| `POST /api/review/skip` | `questionId`，只在当天跳过 |
| `POST /api/review/sessions` | `pointId`、`clientRequestId`，幂等建立复测；同一请求在已答完或设置暂停后仍返回原会话 |
| `GET /api/data/export` | 下载个人资料与练习 JSON，包含简历文件、原文字、来源快照、设置、评估及消耗记录 |

导出不包含录音二进制，不是数据库自动恢复接口。录音需要单独备份 `speech_recordings` 卷；完整恢复使用数据库备份和各数据卷。删除练习复用 P3 的级联清理：追问、回答、评估、录音及转写一起删除；材料删除沿用 P4 语义，旧评估的材料快照保留。

1/3/7 是初始产品规则，不是科学最优间隔，也不承诺面试通过率。当前没有真实多日使用效果数据。
