## 交付范围

- 从已有简历选择一个项目；提取草稿与本人核对的事实卡分开保存。
- 七类事实字段、带出处的文本/Markdown 材料、不可变修订版本及删除当前材料。
- 每项目独立 Chroma 集合，服务端项目/版本过滤；事实卡与补充说明一起作为训练依据，避免公共技术知识或其他项目混入。
- 六类表达模板、四项事实核对、双方原文、待补信息、明确标为未完成的行动建议。
- 不可变回答、异步评估、幂等提交、三次评估上限、重答比较、专项追问及历史快照。
- 项目库、事实卡、练习工作台的桌面及手机布局。

操作、配置、接口和边界见 [项目话术说明](projects.md)。

## 模型质量与失败边界

固定集覆盖职责清楚、职责矛盾、无依据指标、把计划说成已完成、明确未完成改进、缺少测量、完整项目介绍。数据来自虚构项目，预期是人工边界标签。保存输入、来源快照、判定、模型标识、提示词版本与耗时，作为校准证据，不代表未见项目的准确率。

最终实际模型为 `deepseek-flash`，评估规则 `project-facts-v5`，**7/7 条符合预期边界**，单次约 14.9–45.6 秒。输入、预期、实际判定和材料快照见 [最终模型记录](p4-model-evaluation.json)。固定集参与了提示词校准，不能用 7/7 声称通用准确率或真实求职效果。

校准曾发现响应截断及额外字段，输出被拒绝，没有展示成功反馈；初始思考模式的一次校准记录见 [校准数据](p4-model-calibration.json)。曾尝试非思考模式，但计划材料相关约束不稳定，未作为最终配置。最终使用思考模式低强度、16384 输出预算、严格引用上限和计划引用保护。参数依据 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

页面验收的项目介绍重答遇到过两次失败（服务/不完整输出和校验失败），原答与失败评估版本保留；最终重试状态见 HTTP 记录。严格输出校验不等于模型不会失败，来源验证也不等于语义判断永远正确。

同一回答的第三次评估使用最终配置成功，耗时约 18.7 秒。首答为旧规则，和新规则重答之间明确显示不可直接判断改进；再答一次后，两次最终规则评估可以比较。手机职责练习的两次评估使用同一旧规则，正常展示贡献表达从“需要补充”到“已讲清楚”。历史引用按原版本回看，未因本轮校准重写。

## 当前限制

1. 单人自部署、单应用实例；没有账号或跨用户鉴权，独立集合不是公开服务的隐私保障。
2. 判断限于本人确认事实卡和六个检索片段；不能独立证明经历真伪，也不补写成品回答、性能数字或职责。
3. 材料修订后需要开启新练习。旧练习的重答和追问保留旧快照，不能拿新版材料静默改写旧反馈。
4. 删除当前材料不再用于新检索，但旧材料与历史快照仍保存。没有整个项目、全部历史的清除接口。
5. 项目材料编辑框未持久化浏览器草稿；项目/历史列表尚未分页。后台单线程、有限队列适用于个人练习。
6. P4 只提供文字项目表达；P3 的真实 ASR/设备验收和 P5 的掌握度/延迟复测仍未完成。
