# P6 固定样例效果报告

日期：2026-10-03。状态：真实模型评测完成；人工复核与真实试用已移出交付范围。这里报告开发固定集表现，不代表未知回答准确率、用户提升或求职结果。

历史 JSON 中的标签复核状态反映评测当时的情况，不再作为当前待办；预期标签和原始模型记录保持不变。

## 数据与方法

60 条不同回答：保留原 24 条，新增 24 条口语变体和 12 条常见错误。预期判定来自版本化评分依据，未用本次模型输出反向生成标签。新增样例与评分依据比较接近，难度和语言多样性有限；本集没有 PARTIAL 预期标签，部分正确的边界不在本集测量范围内。五项判定差异保留在本报告中。

模型为 `deepseek-flash`，提示词 `p2-criteria-v5`，并发 2，输出上限 8000 tokens，thinking enabled / reasoning low。56 条实际调用模型；4 条无依据样例由程序返回无法判断。保存题目、评分依据、来源快照、模型响应、引用验证、调用参数及内容哈希：[原始记录](p6-model-evaluation.json)、[汇总指标](p6-metrics.json)。两个脚本均对解析后 JSON 计算哈希，但模型报告采用 Java JSON 序列化，检索复测采用 Python 排序键序列化，哈希口径不同，不能直接比较两值。

| 预期事实错误被判正确 | 0/28，0% | 28 项预期 INCORRECT；判 COVERED 或 PARTIAL 均为 0 |

| 实际调用延迟 | P50 6350 ms；P95 15276 ms | 56 次成功调用，最近秩分位数；不含检索 |

平均每次实际模型调用约 3665 tokens。消耗包含供应商返回的完成 tokens，不能据此推导实际费用；费用取决于实际账单、缓存和计价。字段定义参考 [DeepSeek 官方接口](https://api-docs.deepseek.com/api/create-chat-completion/)。

引用验证通过只证明引用存在于对应资料快照、候选人原话来自本次回答，不能证明模型对技术含义的判断必然正确。程序无法判断的 4 条也计入输出校验分母，没有伪装成模型调用。

## 检索故障与恢复

模型评测启动时 Docker 服务尚在恢复，60 次检索中 22 次连接失败。其余调用得到检索结果，其中 37/56 有依据样例命中绑定来源。评测在保留已核验题目资料快照的条件下作有限判定，因此评估失败率 0% **不等于检索服务没有故障**。原始故障记录保留。

服务就绪后另做 [60 次检索复测](p6-retrieval-check.json)：60/60 请求成功；56/56 有依据样例命中与文档 ID、原文和来源地址匹配的资料。4 条无依据样例没有绑定来源。该复测没有重新调用模型，不覆盖原评测结果，也不证明任意查询召回率。

## 五项差异

- `case-17/queue`：预期正确，实际错误。答案先说扩容至最大线程再入队，随后又说先入队，前后矛盾；保留原预期与实际差异。
- `p6-wrong-mysql.isolation/rc`、`rr`：预期缺失，实际错误。错误声明扩展到“都会读到未提交数据”，可能同时覆盖 RC/RR。
- `p6-wrong-spring.proxy/self`：预期缺失，实际错误。“任何调用都被代理拦截”也可能构成自调用错误。
- `p6-wrong-spring.propagation/new`：预期缺失，实际错误。把 REQUIRES_NEW 行为归给 REQUIRED，可能涉及两个要点。

这些差异保留原预期及实际结果，不全部归为模型错误，不更改标签把结果凑到 100%。本轮不再安排人工复核，原始评测记录保持不变。
